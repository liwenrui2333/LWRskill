# 第 1 步：先通读全文（不要跳）

进度条是**观众的观看导航**，不是作者的文稿目录。

动手切段前，必须先在心里回答三个问题。**没答完就切段，标题一定会变成从台词里抠词。**

1. 这条片子在回答观众**哪个问题**？（不是复述内容，是"观众为什么点进来"）
2. 观众先看到什么 → 接着想知道什么 → 后面怎么被回答？（这是**观看路径**，段边界按它划，不按话题或工序变化划）
3. 每一段，观众此刻的疑问**具体是什么**？（段标题就是这句疑问的答案）

---

# 第 2 步：切段

- **段数按内容定，不按固定数。** 默认 3–5 段；总时长 < 60s 只切 2–4 段。
- **同一观看问题的连续内容归一段。** 找参考、检查样片、拆解模板如果都在回答"怎么搭建"，合成一段。
- 切点必须落在**一个完整句子的边界**，用字幕条目的 `start`。
- 第一段从 0 开始（字幕常 0.2–0.6s 才开口，容差 1s），末段收到片尾，相邻不留缝。

---

# 第 3 步：写标题（最常出错，决定观感）

**标题是陈述句或观众的问题，不是名词摘要，更不是台词摘抄。**

| 类型 | 例（同一段） | 判定 |
|---|---|---|
| 台词摘抄 | 七万一千星 / 不是死图片 | ❌ 字对但不知所云，否定句尤其糟 |
| 作者侧概括 | 认识素材库 / 拆解与入库 | ❌ 像文稿目录 |
| 方法论术语 | 论证先行 | ❌ 观众未必懂这个词 |
| **观众问题** | **凭什么七万星 / 哪里不一样** | ✅ |
| **陈述句** | **每一页都能改 / 它先想再画** | ✅ |

出表前逐条过三条硬检查：

1. 把标题连起来读，**是不是一条观看路径**？像目录就重写。
2. 每个标题**单独拎出来能不能看懂**？看不懂就是抠词。
3. 相邻两段**是不是同一阶段的子步骤**？是就合并。

字数 4–6 个汉字，不用括号、引号、标点。

> 实例：一条 34 秒的 PPT-Master 介绍片，初版标题是「七万一千星 / 不是死图片 / 论证先行 / 一句话装上」——四个里三个不合格；改成「凭什么七万星 / 每一页都能改 / 它先想再画 / 一句话装上」才成。

---

# 第 4 步：确认表（固定五列）

| 段落 | 进度条标题 | 这段在讲什么 | 起始原话 | 结束原话 |
| --- | --- | --- | --- | --- |
| 1 | 凭什么七万星 | 用 71k star 数字立悬念 | 据说这是PPT界的天花板 | 它到底牛在哪？ |

**「起始原话 / 结束原话」必须从 SRT 逐字引用**，不能改写成摘要——用户靠这两列核对切点有没有切断句子。

用户说合并/拆分/改标题时，更新整张表再确认一次。不要用纯文字列表替代表格。

---

# 第 5 步：写 chapters.json

```json
{
  "brand": "PPT-Master",
  "series": "七万一千星",
  "duration": 34.319,
  "srt": "example.srt",
  "accent": "red",
  "theme": "dark",
  "position": "top",
  "progress": true,
  "barHeight": 52,
  "width": 1920,
  "canvasHeight": 1080,
  "chapters": [
    {
      "label": "凭什么七万星",
      "start": 0,
      "end": 6.566,
      "startText": "据说这是PPT界的天花板",
      "endText": "它到底牛在哪？"
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `duration` | ✅ | 从 SRT 末条 `end` 取，别手填 |
| `chapters[].start/end` | ✅ | 秒，浮点数 |
| `srt` | 推荐 | 给路径就启用原话核对（见第 6 步） |
| `chapters[].startText/endText` | 推荐 | 逐字引用该段首尾句，缺省则跳过核对 |
| `width` / `canvasHeight` | 无 `--overlay` 时必填 | 画布尺寸，猜错整条要重渲 |
| `barHeight` | | 条高，默认按短边自动算 |
| `theme` | | `dark`（默认）/ `light` |
| `accent` | | `red` / `blue` / `green` / `yellow` |
| `position` | | `top`（默认）/ `bottom` |
| `minSegmentSeconds` | | 段长下限，默认 4 |

---

# 第 6 步：校验

```bash
node scripts/render-chapter-bar.mjs chapters.json --overlay input.mp4 --dry-run
```

脚本会自动检查（不通过直接退出，不生成文件）：

| 检查 | 说明 |
|---|---|
| 首段 start 不在 0 附近（>1s） | 前面有空档没归段 |
| 相邻段留缝 / 重叠 | 时间轴不连续 |
| 末段没收满时长 | 片尾有内容没覆盖 |
| 段短于 `minSegmentSeconds` | 4s 读不完标题 |
| **SRT 原话对不上 / 切点偏移 >0.2s** | **字幕换过了，时间轴不可信** |
| 没给尺寸又没 `--overlay` | 横竖猜错要重渲 |

`--dry-run` 会打印完整的分段表和画布信息，不出文件。

---

# 第 7 步：渲染

**出透明素材（给剪映）：**

```bash
node scripts/render-chapter-bar.mjs chapters.json
```

**直接烧进成片：**

```bash
node scripts/render-chapter-bar.mjs chapters.json --overlay input.mp4
```

加了 `--overlay` 会 ffprobe 源视频，**自动读出宽高和帧率**——竖屏 1080×1920 会自动按竖屏排版，条高也按短边缩放。

> 首次渲染 Remotion 会下载 chrome-headless-shell（约 150MB）。已有浏览器可设 `REMOTION_BROWSER` 指向它，跳过下载。

渲染完成后脚本自动跑 QA：

```
✓ QA 通过：prores / 1920×1080 / alpha / 1030 帧 / 34.32s
```

检查项：编码是 prores、尺寸对、有 alpha 通道、帧数对、时长对、画面中部 alpha=0（透明区没被填底色）。

---

# 第 8 步：人眼验收

透明素材模式会额外生成**联系表**：

```
chapters-contact-sheet.png
```

一张图里是所有章节的「开头 + 中点」，检查三件事：

1. 填充条头和当前高亮的章节名在同一位置
2. 时间码和填充比例对得上
3. 没有两个章节名叠字

**技术检查 ≠ 剪映验收。** 第一次用新样式、或换了剪映大版本，务必真拖进剪映看一次透明有没有变黑——检查全过、剪映里照样黑底，是踩过的坑。

---

# 常见坑

| 症状 | 原因 | 修法 |
|---|---|---|
| 标题看着对，读起来不知所云 | 从台词里抠词 | 回第 1 步答完三问再重写 |
| 竖屏片条宽错位 | 没传 `--overlay`，JSON 又没写尺寸 | 加 `--overlay` 自动探测，或 JSON 写 `width`/`canvasHeight` |
| 字幕改了，条切错位置 | 没写 `srt` + `startText`/`endText` | 补上字段，脚本自动核对并报偏移秒数 |
| 标签全挤在左边 | `duration` 没填 | 从 SRT 末条取 |
| 白条叠在深色画面上很扎眼 | `theme` 用了 light | 改 `dark`（默认值） |
| 章节名糊成一片 | 段太短 | 脚本已拦（`minSegmentSeconds` 默认 4s） |
| 剪映里透明变黑 | 导入时没识别 alpha | 用 ProRes 4444 的 mov；别转 mp4 |
